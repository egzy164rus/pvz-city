# ПВЗ-Сити — симулятор пункта выдачи заказов

**Играть: https://egzy164rus.github.io/pvz-city/** — работает в браузере, ставится как приложение (PWA), играется без интернета.


Играбельный прототип: управленческий симулятор ПВЗ. Сначала вы один — директор, грузчик, продавец и уборщик в одном лице. Потом нанимаете команду и начинаете управлять.

**Запустить:** открыть `index.html` (или `game.html` — это один и тот же автономный билд). Всё в одном файле, интернет не нужен.

## Что уже работает (Срез 0 + ядро глубины)

### Экран запуска
При открытии сначала идёт **премиальный сплэш**: логотип с бегущим бликом, название, шкала загрузки с этапами («Считаем спрос на сегодня», «Подключаем терминал выдачи», «Раскладываем посылки по полкам») и подсказка дня. Тап по экрану — пропустить. Дальше **экран приветствия**: если есть сохранение — крупная кнопка «Продолжить · День N» со сводкой (франшиза, касса, уровень, NPS), рядом «Новая игра»; если сохранения нет — «Начать игру» и четыре фишки о механиках. Первый кадр сплэша нарисован прямо в HTML/CSS, поэтому он виден ещё до разбора скрипта — на медленном телефоне нет белого экрана.

### Визуальный язык (итерация 11)
Тёмная «ночная» тема с зелёным акцентом, крупная типографика и одна главная мысль на экране. **Планировка** — hero-карточка «День N» с тремя плитками (клиенты / посылки / ячейки) и графиком потока по часам с плашкой пика, контракт с KPI-точками, экономика дня в плитках, вкладки продублированы нижним меню. Внизу — **подсказка-CTA**: если день нельзя начать, она прямо говорит, что не так («Не поставлена стойка выдачи — исправить»), и ведёт на нужную вкладку. **День** — коуч-карточка «что делать прямо сейчас» (машина → приёмка → клиент → ремонт), поиск по коду заказа или клиента, очередь с сортировкой по терпению, приёмка чипами, компактные стеллажи с раскрытием по тапу, мини-карта зала и лента событий. **Отчёт** — крупная прибыль/убыток, KPI-плитки, P&L с иконками и блок «Что улучшить».

### Быстрые механики (итерация 11)
- **Схемы расстановки** (`Быстрая выдача` / `Компактно` / `Склад-максимум`) — один тап расставляет всю нерасставленную мебель по готовой схеме.
- **Наборы со скидкой 10 %** — «Стартовый», «Поток клиентов», «Сервис»: покупаются одним нажатием, старт стоит 20 700 ₽ вместо 23 000 ₽.
- **Поиск по коду** — введите код клиента или посылки, игра сама найдёт его в очереди, приёмке или на полке и раскроет нужный стеллаж.
- **Коуч-карточка** — пошагово ведёт по дню и даёт кнопки «Принять всё», «Разложить всё», «Починить».

### Игровой цикл
- **Фаза планирования:** прогноз потока по часам, **планировка зала руками**, закупка мебели и техники, найм, настройка правил склада, кредит.
- **День в реальном времени:** 09:00–21:00 = ~2,5 минуты при 1×, есть 2× и 3× и пауза.
- **Две поставки в день** (09:25 и 15:30) — редкие, но большие: первая привозит ~60% дневного объёма. Приёмка → раскладка по ячейкам. Машина ждёт 5 часов, за неразгруженное — штраф.
- **Выдача как в жизни.** Клиент показывает код → тап по клиенту → **система сама говорит адрес: «Стеллаж Б · ячейка 7»** и подсвечивает нужную ячейку → «Взять» (вы идёте к полке, это занимает время, дальний стеллаж — дольше) → «Выдать» (несёте клиенту). Пока идёте и несёте — вы заняты, и в это время никто не разгружает машину и не обслуживает очередь.
- **Отчёт дня:** P&L (аренда, ФОТ, коммуналка, штрафы, налог раз в неделю, кредит), KPI, совет по проблемам.

### Планировка зала (вы делаете её сами)
- Каждое помещение — сетка: гараж 7×6, спальник 9×7, ТЦ 11×8 клеток. Предметы занимают площадь: стойка 2×1, стеллаж 2×1, стеллаж «Хрупкое» 1×1, КГТ 2×2, примерочная 2×2, баннер/кофемашина/свет 1×1.
- Купили предмет — он падает в палитру «не расставлено» (вкладка **Планировка**, счётчик в заголовке). Выбираете предмет, тапаете клетку — он встаёт. Тап по уже стоящей мебели — «взять и переставить» (посылки на стеллаже переезжают вместе с ним, время ходьбы пересчитывается сразу). Тап по ✕ — убрать (стеллаж с посылками убрать нельзя). Есть кнопка «Расставить автоматически», если не хочется возиться.
- **День не начнётся**, пока нет стойки выдачи, нет ни одного стеллажа и пока хоть один предмет не расставлен, — кнопка «Начать день» блокируется с подсказкой.
- **Планировка = деньги.** Время ходьбы считается честным BFS по проходам: `fetchMinutes = 2 + расстояние_в_клетках × 0.45` (дальше — сканер, усталость, скорость сотрудника). У каждого стеллажа прямо на плане и в дневном экране видно «🚶 N мин». Стеллаж у стойки — быстрые выдачи, но стойку надо ставить так, чтобы к полкам оставался проход: заставили узкий коридор — сами будете обходить.
- Хотите больше склада — ставьте больше стеллажей, но они съедают зал и удлиняют дорогу. Это и есть компромисс планировки.

### Живая карта зала
Во время дня справа под лентой — компактный план зала: серые блоки это мебель, янтарные полосы на стеллажах показывают заполненность, зелёный — стойка. Оранжевый 🧍 — вы; когда идёте за заказом, он честно ползёт по проходам до нужной ячейки (BFS-путь, а не по прямой), а подсвеченная клетка показывает цель. Взяли посылку — значок меняется на 📦 и подпись говорит «у полки, вернитесь к клиенту». Тапнули клиента в очереди — на карте сразу видно, в какую сторону идти.

### Интерфейс без мерцания
Раньше экран перерисовывался целиком ~9 раз в секунду: сбрасывался скролл, дёргались нажатия, перезапускались анимации. Теперь рендер двухслойный:

- **Структура** — страница собрана из участков (`data-r="hud|machine|receiving|queue|log|map|shelves|actionbar|cta"`). После каждого кадра сравнивается HTML участка с тем, что в DOM, и заменяется **только изменившийся**. За день игры это 0 полных пересборок и единицы точечных правок.
- **Быстрые значения** — часы, касса, шкалы терпения, таймер машины, прогресс переноски, позиция человечка на карте — не входят в разметку участков, а обновляются адресно (`liveUpdate`) через `textContent` и `style.width`. Поэтому шкалы плавно анимируются, а не перезапускаются.
- Переключение вкладок в планировке и выбор предмета не сбрасывают прокрутку и не сбивают фокус.

Проверяется автоматически: `test/playtest.mjs` падает, если за 1,5 секунды дня случится хоть одна полная пересборка.

### Возвраты, упаковка, смены и поломки (итерация 9)
- **Клиент приходит только под свою посылку.** Больше нет «пустых» визитов: если на полках нет свободной посылки — человек в зал не заходит. Прогноз в планировании честный: «посылок привезут» всегда ≥ «прогноз клиентов». Отдельно и редко бывают только две роли: вопрос в зале (5%) и клиент с возвратом (9%).
- **Возвраты.** Клиент приносит посылку назад (фиолетовая карточка в очереди, кнопка «Принять», 6–10 минут). Принятые возвраты копятся на стойке — до 4 штук. В 19:00 приходит машина и забирает их сама (+25 ₽ за обработку каждого); можно отправить и раньше, кнопкой. Не отправили до конца дня — 80 ₽ штрафа за каждый.
- **Упаковка.** Купили принтер этикеток — в панели выдачи появляется вторая кнопка «Упаковать +60 ₽»: выдача идёт дольше (лишние минуты), но клиент платит за упаковку и доволен.
- **Смены.** У каждого сотрудника три режима: полный день 09–21 (100% оклада), утро 09–15 и вечер 15–21 (по 62%). Полставки — вдвое дешевле, но в остальные часы он не работает: смены переключаются сами по часам, а в шапке карточки видно «не на смене».
- **Поломки техники.** Сканер, принтер, терминал и кофемашина иногда ломаются (10% шанс за день). Сломанный сканер — +2.5 минуты к поиску заказа, терминал — −6% к выплате, кофемашина не даёт трафик. Ремонт — 30% стоимости предмета, кнопка «Починить» появляется прямо в магазине и в предупреждении над очередью.
- **Машина больше не выбрасывает посылки.** Если зона приёмки занята, поставка ждёт: освободите место и принимайте. Штраф — только если машина уехала, а посылки так и не приняли.

### Панель текущего дела
Внизу, над панелью скоростей, появляется плашка: адрес ячейки («📍 Стеллаж А · ячейка 1»), код клиента и кнопка «Взять» / «Выдать» / «Упаковать» / «На полку». Если никто не выбран, плашка сама предлагает **«Следующий клиент»** — самого срочного, с учётом времени ходьбы до его полки: тап, и вы уже идёте. Не нужно искать нужного клиента и кнопку по всему экрану — действие всегда под большим пальцем, а на карте в это время подсвечена цель. Очередь отсортирована по срочности, а рядом с кодом тикает «сколько ещё минут он готов ждать».

### Команда на карте
Нанятые сотрудники видны на плане зала и двигаются так же честно, как вы: **🧑‍💼 продавец** идёт от стойки к ячейке с заказом клиента (по тому же BFS-пути), **🧑‍🏭 грузчик** таскает посылки от двери разгрузки (низ зала) до свободной ячейки или стоит у двери и принимает машину, **👔 управляющий** держится в зале. Если сотрудников несколько — они не наезжают друг на друга, а расходятся по клетке. Наведение мыши показывает, кто это и чем занят («Пётр · обслуживает»).
Практический смысл: видно, что продавец физически ходит, а не «телепортирует» заказы — и что дальний стеллаж бьёт по времени не только вам, но и команде.

### Примерочные
25% посылок — одежда: клиент хочет примерить. Свободная примерочная = +40 ₽ за услугу и плюс к NPS. Нет примерочной или все заняты (20 игровых минут на клиента) — NPS падает, а в 8% случаев клиент возвращает заказ, и вы теряете половину выплаты.

### Системы глубины
- **Модель спроса** — не рандом: район × бренд × день недели × рост × NPS × кофемашина. Прогноз с погрешностью виден до начала дня.
- **Склад как оптимизация:** размеры S/M/L/XL, хрупкие, зоны (стандарт / хрупкое / КГТ), SLA хранения с автовозвратом. Хрупкое в общей зоне бьётся — реальная потеря денег.
- **Внимание директора:** выдача занимает игровое время, быть в двух местах нельзя. Усталость растёт от ручной работы: на 95% — принудительный перерыв.
- **Персонал как люди:** 4 навыка, характеры (трудяга, педант, душа компании, лентяй, скандалист), настроение, текучка при низком настроении, зарплаты.
- **Контракт маркетплейса:** Бронза → Серебро → Золото → Платина. Требования по скорости выдачи, доле упущенных, NPS и брендбуку. Аудит раз в 7 дней, провал — понижение.
- **Финансы:** УСН 6% раз в неделю, кредит под 0,7%/день с ежедневным платежом, 3 дня в минусе = банкротство.
- **События-дилеммы:** проверка, аванс, скандал на видео, новый тариф, блогер, сломанный кондиционер. У каждого варианта реальная цена.

### Выдача и склад
- Ячейки на стеллажах пронумерованы, адрес считается как «Стеллаж А · ячейка 7». Как далеко стеллаж — зависит от **вашей** планировки: расстояние считается BFS по проходам от стойки, `fetchMinutes = 2 + клетки × 0.45`, сканер ускоряет.
- Пока посылка в руках, её нельзя бросить: либо отдать клиенту, либо «вернуть на полку». Если клиент ушёл — посылка автоматически возвращается на полку.
- Хрупкое в общей зоне может разбиться по дороге (−700 ₽ и минус NPS) — ещё одна причина купить полку «Хрупкое».

### Наём как рубеж
Сотрудник стоит **оформление + аванс зарплаты за 10 дней**. Грузчик = 2 500 + 13 000 = **15 500 ₽** при кассе на старте ~16 000 ₽ и прибыли 2–3 тыс/день. Пока аванс не отработан, зарплата из кассы не списывается; уволили раньше — неотработанный аванс не возвращается. Поэтому первый помощник — событие, к которому копят, а не «куплю апгрейд на второй день».

### Визуальный язык и иконки
Интерфейс собран на **собственном иконочном наборе**: 50 инлайн-SVG-иконок в `src/icons.js` (обводка `currentColor`, 24×24, толщина 1.6–1.8). Системные эмодзи из интерфейса убраны полностью — иконка есть у каждой вкладки, заголовка карточки, кнопки, метрики в HUD, предмета в магазине, детали на плане зала и роли сотрудника.

- `icon(name, cls)` — базовая иконка; `itemIcon(id)` — иконка предмета (стойка → `store`, стеллаж → `shelf`, хрупкое → `fragile`…); `roleIcon(role)` — продавец/грузчик/управляющий.
- Иконки наследуют цвет и размер контекста: `.i` = `1em`, а в кнопках, вкладках, HUD-метриках и токенах карты размер задан точечно.
- Тема: тёмный «стеклянный» слой (`rgba(255,255,255,.045)` → `.012`), hairline-границы, мягкие тени, радиусы 14–22 px, акцентный градиент на главных кнопках и активной вкладке.
- **Свои эмодзи-заменители и в ленте событий:** у строки журнала цветная точка по типу (доставка, событие, уровень, хорошо/плохо), а не картинка.
- Мобильный режим: вкладки на узких экранах становятся иконочными (подпись скрывается, бейдж «Планировка» выносится в угол), кнопки не ниже 44 px, тост показывается над панелью действий по центру.

## Структура проекта

```
index.html         ← готовый билд (всё в одном файле) — открывать этот
game.html          ← тот же билд (для PWA и прямых ссылок)
dev.html           ← dev-версия с ES-модулями (нужен локальный сервер)
src/engine.js      ← движок симуляции: чистая логика, без DOM
src/ui.js          ← интерфейс: экраны, рендер, обработка тапов
src/icons.js       ← 50 инлайн-иконок + маппинг предметов и ролей
src/styles.css     ← стили
build.mjs          ← сборка game.html из src/
sim.mjs            ← headless-симулятор баланса
test/smoke.mjs     ← smoke-тест интерфейса (jsdom)
test/playtest.mjs  ← автоплей дня в реальном Chromium
shot.mjs           ← скриншоты desktop/mobile
manifest.webmanifest, sw.js, icon-*.png  ← PWA
```

### Команды

```bash
node build.mjs                                   # пересобрать game.html
node sim.mjs --days=30 --strategy=balanced       # прогон баланса
node sim.mjs --days=90 --strategy=service --seed=3
node test/economy.mjs                            # юнит-проверки экономики найма
node test/smoke.mjs                              # smoke-тест UI
node test/playtest.mjs                           # автоплей дня
```

Dev-версия с модулями: `npx serve .` → `http://localhost:3000/dev.html`.

Важно: `dev.html` **не откроется** в песочнице предпросмотра (браузер блокирует ES-модули из iframe без своего origin) — для превью и раздачи всегда используйте `index.html` / `game.html`.

## Баланс: где крутить

Все числа — в `CFG` и таблицах в начале `src/engine.js`:

| Что | Где | Сейчас |
|---|---|---|
| Выплата за заказ | `CFG.PAY_BASE` | 100 ₽ × множители |
| Темп дня | `CFG.MIN_PER_SEC` | 5 игровых минут в секунду |
| Терпение клиента | `CFG.PATIENCE_BASE` | 120 игровых минут |
| Время ходьбы за заказ | `fetchMinutes()` | `2 + клетки × 0.45` (BFS от стойки) |
| Передача клиенту | `HANDOVER_MIN` | 2 игровые минуты |
| Штраф за неразгруженную машину | `stepMinute()` | 300 ₽ + 50 ₽ за посылку |
| Налог | `CFG.TAX_RATE` | 6% раз в неделю |
| Кредит | `CFG.LOAN_RATE` | 0,7%/день |
| Аккредитация контракта | `endDay → weeklyAudit` | 12 000 ₽ при повышении |
| Банкротство | `CFG.NEG_DAYS_LIMIT` | 3 дня |
| Наём: аванс | `CFG.PREPAY_DAYS` | 10 дней зарплаты вперёд |
| Наём: оформление | `ROLES.*.onboard` | 2 500 ₽ (управляющий 3 500 ₽) |
| Бренды, помещения, товары, роли, контракты | `BRANDS`, `PREMISES`, `ITEMS`, `ROLES`, `CONTRACTS` | таблицы |

Ориентир баланса (симулятор, сид 7, 30 дней): balanced — выручка 9 160 ₽, прибыль 3 752 ₽/день, контракт «Золото»; service — 9 333 / 4 338 ₽/день; volume — 6 996 / 875 ₽/день (много склада, длинные проходы — сервис проседает). Если после правок balanced уходит в минус или перестаёт расти контракт — сначала смотрите штрафы и время ходьбы.

Проверка после правок:

```bash
node sim.mjs --days=30 --strategy=balanced --seed=7
node sim.mjs --days=30 --strategy=service  --seed=7
node sim.mjs --days=30 --strategy=volume   --seed=7
```

Ориентир: три стратегии должны давать сопоставимый итог с разным риском, а не «одна кнопка победы».

## Приложение (PWA) и GitHub

Игра ставится на телефон как обычное приложение и работает без сети.

- `manifest.webmanifest` — standalone, портретная ориентация, иконки 192/512 + maskable, скриншоты для диалога установки.
- `sw.js` (`pvz-v3`) — оболочка кешируется целиком; навигация «сеть → кеш», ассеты «кеш → сеть».
- `src/ui.js` → `initPwa()`: регистрация воркера, `beforeinstallprompt`, статусы «установлено / в браузере» и «в сети / офлайн», инструкция по установке для iOS/Android.
- `make-icons.mjs` — иконки приложения рендерятся из собственного SVG-знака (тот же куб, что в логотипе).
- `test/pwa.mjs` — проверяет манифест, иконки, активный воркер, кеш и **запуск игры при выключенной сети**.

Локально service worker смотрится так:

```bash
python3 -m http.server 8123     # http://127.0.0.1:8123/index.html
node test/pwa.mjs
```

## Публикация

### Web + PWA
1. Залейте папку целиком на любой статический хостинг (Netlify, Vercel, GitHub Pages, Cloudflare Pages).
2. `manifest.webmanifest` и `sw.js` уже на месте — приложение устанавливается на домашний экран и работает офлайн.
3. Для продакшена поднимите кэш-версию в `sw.js` при релизе.

### Telegram Mini App
1. `@BotFather` → `/newbot` → `/newapp`, укажите HTTPS-URL вашего хостинга.
2. Добавьте в `<head>` подключение SDK:
   ```html
   <script src="https://telegram.org/js/telegram-web-app.js"></script>
   ```
3. Перед `boot()` вызовите `Telegram.WebApp.ready(); Telegram.WebApp.expand();`
   и передайте `tg.themeParams` в CSS-переменные.

### Android
```bash
npm i -D @capacitor/cli @capacitor/core @capacitor/android
npx cap init "ПВЗ-Сити" ru.pvz.city --web-dir=.
npx cap add android
npx cap open android     # сборка AAB в Android Studio
```
